# PortTunnel 使用手册（Linux）

> 适用版本：v0.4.0（linux-amd64 / linux-arm64 / linux-armv7）
> 相关文档：[总体设计](../01-总体设计.md) · [技术栈选型](../02-技术栈选型.md) · [问题处理](./04-问题处理.md)

---

## 1. 组件与端口

| 组件               | 作用                                                  | 默认端口                                                   |
| ------------------ | ----------------------------------------------------- | ---------------------------------------------------------- |
| `ptunnel-server` | 中心服务端：对外暴露代理端口、提供 Web 管理与隧道接入 | 隧道 `8443`（mTLS + 证书注册）、管理台 `9443`（HTTPS） |
| `ptunnel-client` | 部署在内网，主动外连服务端并执行转发                  | 无监听端口                                                 |

代理端口默认范围 `20000-30000`，可在 `server.yaml` 的 `port_range` 调整。

数据流：`用户 → 服务端:代理端口 → 已建立的 mTLS 隧道 → 客户端 → 目标地址:端口`。
客户端只需能**出站**访问服务端 8443，无需公网 IP、无需入站放行。

发布包内容（三种架构结构一致，按服务器 CPU 选择：x86_64 用 amd64、ARMv8 用 arm64、ARMv7 用 armv7）：

```
ptunnel-0.4.0-linux-amd64/     # 或 linux-arm64 / linux-armv7
├── ptunnel-server           # 服务端（已内嵌 Web 管理台）
├── ptunnel-client           # 客户端
├── server.yaml              # 服务端配置示例
├── client.yaml.example      # 客户端配置示例
├── systemd/
│   ├── ptunnel-server.service
│   └── ptunnel-client.service
├── docs/
│   ├── 使用手册.md
│   └── 问题处理.md
└── checksums.txt            # SHA256
```

## 2. 快速开始

### 2.1 启动服务端

```bash
mkdir -p /opt/ptunnel && tar xzf ptunnel-0.4.0-linux-amd64.tar.gz -C /opt/ptunnel --strip-components=1
cd /opt/ptunnel
chmod +x ptunnel-server ptunnel-client
sha256sum -c checksums.txt   # 校验文件完整性

# 首次启动前设置初始管理员口令（不设置则随机生成并在日志中打印一次）
export PTUNNEL_ADMIN_PASSWORD='请改成强口令'

# 前台运行（验证用）
./ptunnel-server -c server.yaml
```

首次启动会自动在 `data/` 生成：

| 文件                            | 说明                                                         |
| ------------------------------- | ------------------------------------------------------------ |
| `ca.crt` / `ca.key`         | 内部 CA，用于签发客户端证书（**ca.key 必须离线备份**） |
| `tunnel.crt` / `tunnel.key` | 隧道端口证书，SAN 取自 `server.tunnel_cert_hosts`          |
| `admin.crt` / `admin.key`   | 管理台 HTTPS 自签证书                                        |
| `ptunnel.db`                  | SQLite（配置、审计、统计）；仅 `storage.driver=sqlite` 时生成 |

浏览器访问 `https://<服务器IP>:9443`，首次会提示自签证书风险，确认继续后登录。
生产环境建议：把实际访问用的域名/IP 加入 `server.tunnel_cert_hosts` 后重启服务端（服务端检测到 SAN 不覆盖会自动重签），或前置正式证书。

> 管理台只能通过 HTTPS 访问；会话 Cookie 为 `Secure`，用 `http://` 打不开登录态。

### 2.2 新建客户端并获取注册令牌

1. 管理台 →「客户端」→「新建客户端」，填写名称（如 `web01`）；
2. 创建成功后会弹出**注册令牌**（15 分钟有效、仅显示一次，用后即失效）；
3. 复制令牌，写入客户端配置。

也可用接口：

```bash
# 登录拿 Cookie 与 CSRF
curl -k -c cookie.txt -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"你的口令"}' https://127.0.0.1:9443/api/auth/login
# 新建客户端（响应中的 enroll_token 即注册令牌）
curl -k -b cookie.txt -H 'Content-Type: application/json' -H "X-CSRF-Token: <csrf_token>" \
  -d '{"name":"web01","remark":"机房A"}' https://127.0.0.1:9443/api/clients
```

### 2.3 首次启动客户端

解包后直接基于示例配置启动，首次只需要填两个值：

```bash
tar xzf ptunnel-0.4.0-linux-amd64.tar.gz
cd ptunnel-0.4.0-linux-amd64
cp client.yaml.example client.yaml
vim client.yaml
```

```yaml
server:
  addr: <服务端地址>:8443        # 必填：客户端可访问的服务端隧道地址
  enroll_token: <注册令牌>       # 必填：管理台创建的 15 分钟一次性令牌
  # cert / key / ca 可以省略，默认写入运行目录：
  #   client.crt / client.key / ca.pem
  # 首次注册成功后 CA 自动下载保存，之后即使清空 enroll_token 也能正常重连
```

启动：

```bash
./ptunnel-client -c client.yaml
```

首次启动流程：

1. 本地生成私钥与 CSR（私钥不出机器）；
2. 用令牌向服务端换发客户端证书，证书与 CA 分别写入 `cert` / `key` / `ca`（未配置则用默认文件名）；
   注册阶段服务端证书尚未被信任，会跳过校验并打印一条警告；注册成功后 CA 落地，之后所有连接都做严格校验；
3. 建立 mTLS 隧道，上报本地代理列表；
4. 服务端把未审批的本地代理记为「待审批」，管理员在「端口代理」页通过后立刻生效。

前台看到 `隧道已建立` 日志即表示首次注册完成，再交给 systemd 托管（见第 5 节）。

> 令牌使用后即失效，`client.yaml` 中的 `enroll_token` 可以清空。证书有效期 90 天，剩余不足 30 天时客户端会自动续期并重连。

需要本地登记代理时再补充 `security.allow_targets` 与 `proxies`（见 3.2）；如果代理都由服务端配置，`proxies` 可以留空，直接按 2.4 在管理台新建即可。

### 2.4 在服务端配置代理（推荐方式）

管理台 →「端口代理」→「新建代理」：

| 字段           | 说明                                                     |
| -------------- | -------------------------------------------------------- |
| 客户端         | 选择目标客户端                                           |
| 监听地址       | 一般 `0.0.0.0`；只对内网开放可填内网 IP                |
| 服务端端口     | 用户访问的端口，须在 `port_range` 内且不与已有规则冲突 |
| 转发目标       | `客户端可访问的地址:端口`，如 `10.1.2.3:3000`        |
| 应用类型       | 可选：MySQL / PostgreSQL / SQL Server / Oracle / 达梦 / Redis / MongoDB；绑定后解析并审计 SQL 或命令 |
| 来源 IP 白名单 | 每行一个 CIDR，留空不限制                                |
| 最大连接数     | 0 表示使用全局默认                                       |
| 启用           | 保存后立即监听（无需重启）                               |

### 2.5 验证

```bash
# 从外部机器访问
curl http://<服务端IP>:23306/

# 服务端健康检查
curl -k https://127.0.0.1:9443/healthz
# {"status":"ok","db":true,"clients":1,"listeners":1,...}
```

管理台 →「连接审计」可看到该次访问：来源 IP/端口/MAC、服务端端口、客户端、代理、目标地址、开始/结束时间、时长、双向字节、结束原因。

### 2.6 SQL 语句审计（可选）

给代理绑定「应用类型」后，服务端会从**未加密**的数据库/中间件协议中提取客户端发出的语句，写入本地日志文件：

- 存储位置：`data/sqllogs/sql-YYYY-MM-DD.log`（JSON Lines），每天 00:00 自动切换；
- 次日自动 gzip 压缩为 `sql-YYYY-MM-DD.log.gz`，超过 `audit.sql_log_retention_days`（默认 30 天）自动删除；
- 管理台 →「SQL 审计」可查询**当天**或历史日期，支持按来源 IP、MAC、应用类型、SQL 关键字过滤；
- 记录内容：时间、来源 IP/端口/MAC、客户端、代理、目标地址、应用类型、语句类型、SQL 文本。

各应用的提取方式：

| 应用 | 提取内容 | 说明 |
| --- | --- | --- |
| MySQL / MariaDB | COM_QUERY、COM_STMT_PREPARE 中的 SQL | 明文连接 |
| PostgreSQL | Query('Q')、Parse('P') 中的 SQL | 明文连接 |
| SQL Server | TDS SQL Batch（UTF-16） | 明文连接 |
| Redis | RESP 命令（如 `SET k v`） | 明文连接 |
| MongoDB | OP_MSG 命令 + 集合名（如 `find users`） | 明文连接 |
| Oracle / 达梦 | 启发式提取以 SQL 关键字开头的文本 | 协议为私有编码，**可能漏报/误报** |

> 限制：客户端使用 TLS/SSL 连接到数据库（如 MySQL `--ssl-mode=REQUIRED`、PostgreSQL `sslmode=require`）时，隧道里是加密流量，无法解析语句，只会保留连接审计；单条语句按 `audit.sql_statement_max_len`（默认 4096 字符）截断。

## 3. 配置说明

### 3.1 server.yaml

| 配置项                            | 默认                    | 说明                                           |
| --------------------------------- | ----------------------- | ---------------------------------------------- |
| `server.tunnel_addr`            | `0.0.0.0:8443`        | 隧道与客户端注册/续期接口共用端口（ALPN 分流，管理面不在该端口暴露） |
| `server.admin_addr`             | `0.0.0.0:9443`        | 管理台 HTTPS                                   |
| `server.public_bind`            | `0.0.0.0`             | 代理端口默认绑定地址                           |
| `server.port_range`             | `[20000, 30000]`      | 允许映射的端口范围                             |
| `server.tunnel_cert_hosts`      | `localhost,127.0.0.1` | 自动签发证书的 SAN，客户端用域名访问时必须包含 |
| `server.pprof_addr`             | 空                      | 可选 pprof 调试监听地址（如 `127.0.0.1:6060`），留空不启动；仅建议内网/本机开放 |
| `storage.driver`                | `sqlite`              | `sqlite`（本地，默认）/ `mysql`             |
| `storage.data_dir`              | `./data`              | 数据目录（CA、证书、SQL 审计文件；MySQL 模式下仍需要） |
| `storage.sqlite_path`           | 空                      | 留空使用 `data_dir/ptunnel.db`（`driver=sqlite` 时生效） |
| `storage.mysql.dsn`             | 空                      | MySQL DSN，`driver=mysql` 时必填，见 5.7      |
| `storage.mysql.max_open_conns`  | `20`                  | 连接池上限                                     |
| `storage.mysql.max_idle_conns`  | `10`                  | 空闲连接数                                     |
| `storage.mysql.conn_max_lifetime` | `30m`               | 连接最长存活时间                               |
| `auth.session_ttl`              | `12h`                 | 管理会话有效期                                 |
| `auth.login_rate_limit`         | `10`                  | 每 IP 登录失败上限（超过锁 1 分钟）            |
| `tunnel.heartbeat`              | `15s`                 | 心跳周期，超过 3 倍未响应判定离线              |
| `tunnel.idle_timeout`           | `5m`                  | 转发连接空闲超时（0 表示不限）                 |
| `tunnel.handshake_timeout`      | `10s`                 | 等待客户端控制流/握手的超时                    |
| `tunnel.max_streams_per_client` | `4096`                | 单客户端并发隧道流上限（超出拒绝新连接）       |
| `tunnel.max_conns_per_client`   | `0`                   | 单客户端并发连接上限（0 不限；与上一项取较小值） |
| `tunnel.half_close_grace`       | `500ms`               | 一端结束后等待另一方向收尾的时长；短连接多时可调小，`0` 表示立即关闭 |
| `tunnel.auto_approve_local`     | `false`               | 客户端本地登记是否自动通过审批                 |
| `tunnel.max_conns_per_proxy`    | `0`                   | 全局默认单代理连接上限                         |
| `audit.conn_log_mode`           | `full`                | `full` / `sample` / `off`                |
| `audit.conn_log_sample_rate`    | `1`                   | 采样模式下每 N 条记 1 条                       |
| `audit.conn_log_retention_days` | `30`                  | 明细保留天数，每日 03:00 清理                  |
| `audit.conn_log_queue_size`     | `10000`               | 内存队列，满则丢弃并计数（不阻塞转发）         |
| `audit.mac_lookup`              | `true`                | 是否查询邻居表获取来源 MAC（仅同网段有效）     |
| `audit.sql_log_enabled`         | `true`                | 是否启用 SQL 语句审计（仅对绑定了应用类型的代理生效） |
| `audit.sql_log_dir`             | `data_dir/sqllogs`    | SQL 日志目录（按天分割、自动 gzip）            |
| `audit.sql_log_retention_days`  | `30`                  | SQL 日志保留天数（0 表示不清理）               |
| `audit.sql_statement_max_len`   | `4096`                | 单条语句最大记录字符数，超出截断               |

> 说明：管理台「系统设置」里保存的审计模式与保留天数会写入数据库，并在服务端启动时**优先于** `server.yaml` 生效（修改后需重启）。若之后希望改回配置文件的值，请在管理台重新保存一次对应项。

### 3.2 client.yaml

| 配置项                           | 说明                                                                 |
| -------------------------------- | -------------------------------------------------------------------- |
| `server.addr`                  | 服务端隧道地址，必须能被客户端访问                                   |
| `server.ca`                    | 服务端 CA；首次注册无此文件时会跳过校验（可配 `fingerprint` 固定） |
| `server.fingerprint`           | 服务端证书 SHA256 指纹，格式 `sha256:...`，用于首次信任            |
| `server.cert` / `server.key` | 客户端证书与私钥路径（首次注册自动生成）                             |
| `server.name`                  | 客户端名称（仅注册时使用）                                           |
| `server.enroll_token`          | 一次性注册令牌（注册成功后失效）                                     |
| `tunnel.reconnect_min/max`     | 重连退避区间（指数退避 + 抖动）                                      |
| `tunnel.heartbeat`             | 心跳周期，建议与服务端一致                                           |
| `tunnel.dial_timeout`          | 连接目标地址超时                                                     |
| `tunnel.half_close_grace`      | 客户端侧收尾等待，建议与服务端一致；`0` 表示立即关闭                  |
| `security.allow_targets`       | 本地目标白名单（CIDR），服务端下发的目标超出范围会被拒绝应用         |
| `proxies[]`                    | 本地登记的代理：`name`、`protocol`、`remote_port`、`target`  |

## 4. 管理台功能

| 页面     | 功能                                                                                  |
| -------- | ------------------------------------------------------------------------------------- |
| 仪表盘   | 在线客户端、监听端口数、活跃连接、今日连接/流量、24 小时曲线、最近访问；运维检测（CPU/内存/Goroutine/线程、隧道会话、监听端口、在途连接明细） |
| 客户端   | 新建、生成注册令牌、启用/禁用、吊销证书、删除；显示在线状态、版本、心跳时间、待审批数 |
| 端口代理 | 增删改、启停、审批本地登记、来源白名单、连接数上限、监听状态与实时统计                |
| 连接审计 | 按客户端/代理/来源 IP/端口/时间筛选，查看详情，导出 CSV（最多 10 万行）               |
| SQL 审计 | 按日期（默认今天）/来源 IP/MAC/应用/关键字查询 SQL 语句，查看完整语句与连接上下文     |
| 操作审计 | 登录、配置变更等操作记录（操作者、IP、时间、详情）                                    |
| 系统设置 | 运行信息、审计保留天数/模式、修改管理口令                                             |

## 5. 运维

### 5.1 systemd 部署

```bash
sudo useradd -r -s /usr/sbin/nologin ptunnel
sudo mkdir -p /opt/ptunnel /opt/ptunnel/data
sudo chown -R ptunnel:ptunnel /opt/ptunnel
sudo cp ptunnel-server ptunnel-client server.yaml client.yaml /opt/ptunnel/
sudo cp systemd/ptunnel-server.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now ptunnel-server
sudo journalctl -u ptunnel-server -f
```

客户端同理（`ptunnel-client.service`，`WorkingDirectory=/opt/ptunnel`）。

### 5.2 监控

- `GET /healthz`：DB、在线客户端数、监听数、运行时长、审计队列长度；
- `GET /metrics`：Prometheus 文本格式（`ptunnel_client_online`、`ptunnel_proxy_listeners`、`ptunnel_active_conns`、`ptunnel_bytes_total`、`ptunnel_rejected_total`、`ptunnel_connlog_dropped_total` 等）；
- `GET /api/system/runtime`（需登录）：进程 CPU/内存/线程/句柄、Go 堆与 Goroutine、在线隧道会话、监听端口和在途连接明细，仪表盘「运维检测」每 5 秒刷新一次；
- 日志：JSON 输出到 stdout，建议由 `journald` / Docker 收集。
- 排障：如需 goroutine/内存快照，可在 `server.yaml` 配置 `server.pprof_addr: 127.0.0.1:6060`，通过 `go tool pprof http://127.0.0.1:6060/debug/pprof/...` 采集；该端口默认关闭，且未鉴权，切勿暴露公网。

### 5.3 备份

**必须备份**：

```
data/ptunnel.db      # SQLite 模式：配置与审计
data/ca.crt + ca.key # 内部 CA，丢失后所有客户端需重新注册
data/tunnel.* admin.* # 服务端证书
```

MySQL 模式下额外用 `mysqldump` 备份 `ptunnel` 库（配置与连接审计在库中，SQL 语句审计文件仍在本地 `data/sqllogs`）。

建议每日备份 `data/` 目录，`ca.key` 单独离线保存。

### 5.4 升级

1. 备份 `data/`；
2. 替换二进制（`ptunnel-server`、`ptunnel-client`）；
3. `systemctl restart ptunnel-server`，数据库自动迁移（仅向前）。

客户端版本通过控制协议协商，服务端向后兼容一个小版本。

### 5.5 忘记管理口令

```bash
sudo systemctl stop ptunnel-server
sudo -u ptunnel /opt/ptunnel/ptunnel-server -c /opt/ptunnel/server.yaml -reset-password '新口令至少8位'
sudo systemctl start ptunnel-server
```

### 5.6 客户端证书吊销 / 换机

- 管理台 →「客户端」→「吊销证书」：立即断开在线会话，旧证书无法再建立隧道；
- 换机或重装：吊销旧证书 →「注册令牌」重新生成 → 客户端删除本地 `client.crt`/`client.key` 后用新令牌启动。

### 5.7 使用 MySQL 存储（可选）

默认使用内嵌 SQLite，零运维即可运行。若需要集中备份或统一数据库运维，可切到 MySQL 8.0 / 5.7。

1）建库授权（示例）：

```sql
CREATE DATABASE ptunnel DEFAULT CHARSET utf8mb4 COLLATE utf8mb4_general_ci;
CREATE USER 'ptunnel'@'%' IDENTIFIED BY '改成强口令';
GRANT ALL PRIVILEGES ON ptunnel.* TO 'ptunnel'@'%';
FLUSH PRIVILEGES;
```

2）修改 `server.yaml`：

```yaml
storage:
  driver: mysql
  data_dir: ./data                 # CA/证书/SQL 审计文件仍存本地
  mysql:
    dsn: "ptunnel:改成强口令@tcp(127.0.0.1:3306)/ptunnel?charset=utf8mb4&parseTime=true&loc=Local"
    max_open_conns: 20
    max_idle_conns: 10
    conn_max_lifetime: 30m
```

3）重启服务端，日志出现 `"msg":"数据库已就绪","driver":"mysql"` 即切换成功。

说明：

- 表结构首次启动自动创建（`schema_migrations` 记录已执行脚本），无需手工导入 SQL；
- **不自动迁移历史数据**：需要保留原 SQLite 记录时，请自行导出后导入 MySQL（表名与字段一致，时间均为 Unix 毫秒整数）；
- 本地 `data/` 目录仍必需：内部 CA、隧道/管理证书、SQL 语句审计文件都落本地磁盘，不入库；
- 仍是单活服务端：多个服务端进程不要同时连同一个库对外提供同一批端口映射。

---

## 6. 安全建议

1. 管理台不要直接暴露公网，限制来源 IP（安全组/防火墙）；
2. 隧道端口 8443 建议只放行客户端出口 IP 段；
3. 代理规则尽量配置来源 IP 白名单，避免端口被扫描滥用；
4. 客户端 `allow_targets` 必须收紧到实际需要的网段，防止服务端配置错误或被盗用时横向扩散；
5. 定期检查「连接审计」中的 `rejected`、`target_unreachable` 记录；
6. `data/ca.key` 权限保持 `0600`，不要提交到代码仓库。

---

## 7. 已知限制

- 仅支持 TCP 转发（UDP 未实现）；
- 不支持 HTTP 域名/路径级路由；
- 单机部署（SQLite / MySQL），无多节点高可用；
- MAC 地址仅在客户端/访问者与服务端同二层时可得，跨网段/公网为空；
- 管理台与隧道证书默认自签，生产环境请使用可信证书或分发给客户端 CA；
- 单条连接在一端结束后按 `tunnel.half_close_grace`（默认 `500ms`）等待另一方向收尾，因此审计中的时长可能比实际业务时长多约 0.5 秒；大量短连接场景可适当调小。
